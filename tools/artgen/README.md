# artgen — генерация ассетов по промпт-буку

Запрашивает изображения у OpenRouter по промптам из
[docs/gdx/05-prompt-book-v2-calm-ui.md](../../docs/gdx/05-prompt-book-v2-calm-ui.md),
проверяет результат измеримыми метриками, при провале повторяет запрос с исправляющей
фразой из §9 того же бука и раскладывает принятое по адресам, которые в буке и указаны.

Промпты здесь не дублируются. Единственный источник истины — бук; скрипт из него читает
и текст запроса, и формат, и пороги проверок, и список имён для нарезки листов.

## Ключ

```
mkdir -p ~/.config/openrouter && chmod 600 ~/.config/openrouter/key
```

Либо переменная `OPENROUTER_API_KEY`. В репозиторий ключ не попадает.

## Команды

```bash
python3 tools/artgen/artgen.py sections               # что вообще есть в буке
python3 tools/artgen/artgen.py batch 3                # вся глава: карты
python3 tools/artgen/artgen.py batch 4.4,4.9          # выборочно
python3 tools/artgen/artgen.py gen 4.4 --seed 7       # одна попытка, повторяемая
python3 tools/artgen/artgen.py compare 2.1            # один промпт на трёх моделях
python3 tools/artgen/artgen.py check 3.2 файл --judge # проверки + vision-судья
python3 tools/artgen/artgen.py accept 3.2 файл        # принять: положить и записать в лог
python3 tools/artgen/sheet.py лист.png a.png=подпись  # контактный лист для приёмки
```

Кандидаты падают в `assets_src/raw/attempts/`, каждый запрос пишется строкой в
`tools/artgen/runs.jsonl` — с моделью, ценой, метриками и найденными замечаниями.

## Что проверяется

Механически, в [checks.py](checks.py), с порогами из текста самого промпта:

| Проверка | Откуда порог |
|---|---|
| соотношение сторон и размер | `aspect ratio 2:3, size 1024x1536` |
| чистота фона по периметру | `pure-white background` / `pure-black background` |
| поля вокруг объекта | `Leave 5% empty margin on all sides` |
| доля светлых пикселей | `Bright highlights occupy less than 8%` |
| число объектов на листе | список имён после «Нарезать» |

Фон определяется заливкой от краёв с допуском, а не по абсолютному цвету — тем же
приёмом, что в `SheetSlicer.kt`, иначе светлые части объекта считаются фоном. Яркость
и насыщенность считаются только внутри объекта: на белом холсте фон иначе забивает метрику.

Отдельно `audit` сравнивает ассеты между собой — как просит §11 бука. Абсолютного порога
яркости у большинства промптов нет, а выпадение из общей гаммы видно только в сравнении:
так нашлась слишком светлая урна сброса (яркость 59.8 против медианы 41.3 по набору).

У ассетов с замкнутым контуром — слот под карту, рама портрета — заливка от краёв не
достаёт до середины, и белый фон внутри кольца считается частью объекта. Их яркость
и насыщенность в `audit` смотреть бессмысленно; в `sliceSheet` для этого есть `-Pholes`.

Vision-судьёй (`--judge`, `openai/gpt-5-nano`) проверяется то, что метрикам недоступно:
скопированный из референса текст, оранжевое дерево, цветное свечение на нейтральных
поверхностях. Его находки помечаются как «внимание», а не как провал: модель ошибается.

Чего не проверяет никто, кроме человека: качество живописи и принадлежность к одному
набору. Для этого и нужен контактный лист.

## Выбор модели

Сравнение на §2.1 (перерисовка эталонной карты F), три модели, один промпт и одни референсы:

| Модель | Формат | Цена | Итог |
|---|---|---|---|
| `openai/gpt-5.4-image-2` | 1024×1536 | $0.048 | **выбрана**: насыщенность 0.26, поля 6–10% |
| `google/gemini-3-pro-image` | 1696×2528 | $0.138 | живописнее, но насыщенность 0.367 и тёплое дерево |
| `openai/gpt-5-image` | 1024×1536 | $0.263 | нижнее поле 0.8%, рамка ушла в чёрный |

Известные ограничения: на соотношении 1:1 OpenAI-модели отдают максимум 1024×1024,
заказанные буком 1536×1536 недостижимы. Для листов иконок это ~256 px на иконку —
при целевых 24–48 px запаса хватает.

## Почему `/api/v1/images`, а не chat completions

Через chat completions OpenAI-модели игнорируют требуемый формат и всегда отдают
1024×1024: вертикальная карта при этом обрезается, теряя нижний самоцвет. Отдельный
эндпоинт принимает `aspect_ratio`, `resolution` и `seed`, отдаёт точный размер и
обходится втрое дешевле, потому что не тратит reasoning-токены.

## Дальше по конвейеру

После приёмки ассеты подхватывает существующий Kotlin-инструментарий:

```bash
cd gdx
./gradlew tools:sliceSheet -Psheet=../assets_src/raw/sheet_buttons.png -Ptolerance=8 \
  -Pnames=btn_primary_up,btn_primary_hover,btn_primary_down,btn_secondary_up,btn_secondary_down,btn_primary_disabled \
  -Pout=../assets_src/ui
./gradlew tools:prepareBackgrounds
./gradlew tools:packAtlases
```

Три вещи, которые стоили итераций и в буке не описаны:

**`-Ptolerance=8` почти всегда обязателен.** Ассеты v2 темнее и с более мягкой кромкой,
чем v1, и допуск по умолчанию пробивает границу объекта: кубики и урна вырезались в ноль,
а стопка колоды — в полоску 801×102 вместо 801×843.

**`-Psolid` нельзя давать вогнутым силуэтам.** Флаг заливает «дыры» внутри контура обратно,
а у геральдического щита вогнутые бока считаются дырами — эмблема приезжала в игру
с белым прямоугольником. Кольцу и слоту нужен `-Pholes`, щиту и кругу — ни того, ни другого.

**Карты тоже режутся.** В v1 они лежат RGBA с вырезанным фоном; если положить их как RGB
прямо из генерации, под каждой картой в руке окажется белый прямоугольник.

Листы VFX по связным областям не разбираются вообще: руническое кольцо по заданию состоит
из разрозненных глифов, а мягкое свечение не имеет границы. Для них есть
[slice_grid.py](slice_grid.py) — режет по ячейкам сетки и берёт альфу из яркости:

```bash
python3 tools/artgen/slice_grid.py assets_src/raw/sheet_vfx_neutral.png 2x4 assets_src/vfx \
  fx_glow_soft,fx_burst_star,fx_ring_rune,fx_shockwave,fx_spark,fx_dust,fx_smoke_puff,fx_lightray
```

Имена иконок для §4.9 нужно задавать явно: бук говорит «нарезать в прежнем порядке»,
но порядок символов v2 отличается от v1 на позициях 6, 7, 8 и 15.

```
icon_settings,icon_sound_on,icon_sound_off,icon_music_on,icon_music_off,icon_rules,
icon_menu,icon_close,icon_restart,icon_back,icon_hourglass,icon_deck,icon_hand,
icon_speed,icon_duel,icon_info
```
