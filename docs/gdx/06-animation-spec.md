# 06 — Спецификация анимаций и VFX

Принцип: **анимации мало, но она наглядная.** Каждая анимация обязана объяснять игроку, что произошло по правилам. Украшательства без смысла не добавляем — они удлиняют ход и раздражают на повторных партиях.

Технически всё делается на **Scene2D Actions** и **ParticleEffect** из статичных текстур [04-asset-list.md](04-asset-list.md) §5. Покадровых спрайт-анимаций нет.

## 1. Правила проигрывания

- `AnimationDirector` получает список `GameEvent` от движка и проигрывает их **последовательно**, блокируя ввод.
- Каждое событие → `SequenceAction`. Параллельные части — `ParallelAction`.
- Настройка **скорости анимаций**: `Normal` (×1.0), `Fast` (×0.6), `Instant` (×0.0 — всё телепортируется). Множитель применяется ко всем `duration` централизованно.
- Тап по экрану во время проигрывания — **пропустить текущую очередь** (доиграть мгновенно). Это уважение к игроку, который уже видел эффект сто раз.
- Бюджет: полный ход ИИ (добор → розыгрыш → эффект → передача хода) укладывается в **≤ 2.5 с** при `Normal`.

## 4. Что осознанно **не** анимируем

- Пересчёт счётчиков в HUD — просто меняем число (мигание отвлекает).
- Прокрутка лога боя — мгновенная.
- Раскрытие карт ИИ в руке — рука ИИ вообще не отрисовывается покарточно, только счётчик.
- Ландшафт/фон — статичен. Единственное исключение: очень медленное мерцание свечей (шейдером или пульсацией альфы двух спрайтов).

## 5. Реализация: скелет

```kotlin
class AnimationDirector(private val stage: Stage, private val speed: () -> Float) {
    private val queue = ArrayDeque<GameEvent>()
    private var busy = false

    fun enqueue(events: List<GameEvent>) { queue.addAll(events); pump() }

    private fun pump() {
        if (busy) return
        val event = queue.removeFirstOrNull() ?: run { onIdle(); return }
        busy = true
        buildAction(event).then { busy = false; pump() }.also { stage.addAction(it) }
    }

    fun skipAll() { /* завершить все Actions мгновенно, применить конечные состояния */ }
}
```

Ключевое: `AnimationDirector` **не меняет игровое состояние** — оно уже изменено движком. Он лишь приводит визуал в соответствие с новым состоянием. Если анимация упадёт с исключением, игра останется корректной.

## 6. Производительность

- Одновременно активных партикл-эффектов — не более 3.
- Все VFX-спрайты в одном атласе `vfx.atlas` → один draw call на группу.
- Тряска экрана — сдвиг камеры, а не пересчёт лэйаута.
- Цель: **60 FPS на телефоне 2019 года** и в вебе на среднем ноутбуке. Проверяем на M8.
