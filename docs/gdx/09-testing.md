# 09 — Тестирование

Главный выигрыш новой архитектуры: правила живут в чистом Kotlin без libGDX, поэтому проверяются обычными быстрыми JVM-тестами. Именно здесь ловятся баги вроде тех, что чинились коммитами `fix trap logic`.

## 1. Уровни

| Уровень | Инструмент | Что покрывает | Где |
|---|---|---|---|
| Unit | `kotlin.test`, запуск на JVM (JUnit 5) и на Node | `GameEngine`, эффекты, условия победы, лимиты | `rules/src/commonTest/kotlin/domain/` |
| Сценарные | `kotlin.test`, детерминированный `Rng(seed)` | Партии целиком по заданным колодам | `rules/src/commonTest/kotlin/domain/` |
| Свойства (property-based) | `kotlin.test` | Инварианты на 200 случайных партиях | `rules/src/commonTest/kotlin/domain/InvariantTest.kt` |
| ИИ | `kotlin.test` | ИИ никогда не выбирает недопустимый ход; Hard бьёт Easy в ≥70 % из 1000 партий | `rules/src/commonTest/kotlin/domain/ai/` |
| Сохранение | JUnit 5 | Кодирование и разбор отложенной партии | `core/src/test/kotlin/com/first/game/SaveGameTest.kt` |
| Ручные | чек-лист | UI, анимации, звук, платформы | `docs/gdx/CHECKLIST-manual.md` (создаётся на M5) |

Тесты презентационного слоя автоматически **не** пишем: цена поддержки выше пользы. Визуал проверяется руками по чек-листу.

## 2. Детерминированность

`GameEngine` не должен обращаться к глобальному генератору случайных чисел. Всё через инжектируемый интерфейс:

```kotlin
interface Rng { fun nextInt(bound: Int): Int }
class SeededRng(seed: Long) : Rng
class ScriptedRng(private val values: List<Int>) : Rng   // для тестов
```

Это позволяет задать точный порядок колоды и воспроизвести любой баг по сиду.

## 3. Обязательный набор сценариев

Перенести из `tests/manual_test_checklist.md` и `tests/automated_scenario_tests.html`, дополнив краевыми случаями из [01-rules-spec.md](01-rules-spec.md).

### 3.1 Инициализация
- [ ] Колода — ровно 50 карт, по 10 каждой буквы
- [ ] После раздачи: 5 в руке, 45 в колоде у каждой стороны
- [ ] Кубики при равенстве перебрасываются, пока значения не разойдутся
- [ ] Первый игрок не берёт карту в первый ход; второй — берёт

### 3.2 F (FORBID)
- [ ] Запрет можно поставить на любую из 5 букв
- [ ] Оппонент играет запрещённую букву → карта в его сброс, SPACE не меняется, эффект не срабатывает, ход завершается
- [ ] После срабатывания запрет снят
- [ ] Повторное F перезаписывает предыдущий запрет, а не добавляет второй
- [ ] Запрет на букву, которой у оппонента нет, не мешает ничему
- [ ] Запрет висит неограниченно долго, если не сработал

### 3.3 I (INCREASE)
- [ ] +1 карта в руку, −1 в колоде
- [ ] При полной руке (7) добор приводит к немедленному сбросу последней карты
- [ ] Пустая колода в момент эффекта I → поражение владельца

### 3.4 R (RECOVER)
- [ ] Пустой сброс → эффект не срабатывает, ход продолжается штатно
- [ ] Возвращается именно выбранная буква, из сброса удаляется одно вхождение
- [ ] Возврат при 7 картах в руке → карта тут же уходит в сброс (проверить, что не зациклится)

### 3.5 S (STEAL)
- [ ] Пустой SPACE оппонента → эффект не срабатывает
- [ ] Выбранная карта уходит в сброс **оппонента**, не в свой
- [ ] Карта, убранная из SPACE, перестаёт учитываться в условиях победы
- [ ] Кража последней карты из SPACE не ломает раскладку

### 3.6 T (TRAP)
- [ ] Ловушка срабатывает в начале следующего хода оппонента
- [ ] После сброса по ловушке оппонент **всё равно** делает свой ход
- [ ] Пустая рука оппонента → ловушка гасится без эффекта
- [ ] Две ловушки подряд: поведение согласно принятому решению **D-3** (декремент — два сброса в двух ходах)

### 3.7 Победа и поражение
- [ ] Все 5 разных букв в SPACE → победа (порядок не важен — решение **D-1**)
- [ ] 5 одинаковых букв в SPACE → победа
- [ ] Пустая колода в фазе добора → поражение владельца колоды
- [ ] После завершения партии никакие действия не принимаются
- [ ] Игра корректно завершается, если победное условие возникло у ИИ

### 3.8 Лимит руки
- [ ] Рука никогда не превышает 7 карт
- [ ] Сбрасывается последняя добранная карта (решение **D-2**)
- [ ] Добор при полной руке сжигает карту колоды

### 3.9 Инварианты (property-based, 10 000 партий)
- [ ] Сумма `deck + hand + space + discard` каждой стороны **всегда равна 50**
- [ ] Количество карт каждой буквы у стороны всегда ровно 10
- [ ] Партия всегда завершается за конечное число ходов (< 200)
- [ ] Ход всегда переходит к оппоненту, кроме завершённой партии
- [ ] Ни одно состояние не позволяет сделать ход обеим сторонам одновременно

## 4. Ручной чек-лист (M5–M8)

Помимо игровой логики проверяем:
- обе локали на каждом экране, без обрезки и вылезания текста;
- landscape и portrait на телефоне и планшете;
- вырезы экрана (iPhone с «чёлкой», Android с точкой);
- сворачивание/разворачивание приложения во время анимации;
- поворот экрана во время анимации;
- потерю фокуса вкладки в вебе;
- пропуск анимаций тапом в любой момент;
- отключение звука и перезапуск приложения (настройки сохранились).

## 5. Регресс перед релизом

Полный прогон §3 автоматически (`./gradlew core:test`) + §4 вручную на четырёх платформах. Результат фиксируется в описании релиза.
